# Design system

## Primitives

`TabsList variant="bold"` gives the large tab bar (48 px buttons, the chosen one a raised primary button whose icon wiggles; on phones icon above label): use it for a page's or panel's main sections. shadcn/ui components (Radix underneath) copied into `src/components/ui/` and edited for our look: `Button` (variants `default`, `secondary`, `outline`, `ghost`, `destructive`, `success`, `link`; sizes `sm`, `default` (48 px), `lg`, `xl`, `icon`, `icon-sm`), `Card`, `Input`, `Textarea`, `Label`, `Select`, `Switch`, `Checkbox`, `RadioGroup`, `Dialog`, `Sheet`, `Tabs`, `Badge`, `Tooltip`, `DropdownMenu`, `Popover` and `PopoverAnchor` (written by hand like the shadcn ones; opens with `animate-bubble-pop`), `Skeleton`, `Separator`, `Progress`, `Toaster` (Sonner). `DropdownMenuSub` / `SubTrigger` / `SubContent` look like the menu's items and content; the sub content renders in its own portal, because the parent menu's pop animation would clip and offset a nested one. Add more with `pnpm dlx shadcn@latest add <name>` from `apps/web`, then run prettier on that one file (the repo as a whole is not Prettier-formatted, so never run it wider) and replace any hard-coded English text (e.g. "Close") with `t()`. Dialog and sheet X buttons share `closeButtonClass` (`ui/dialog.tsx`); a new overlay primitive uses it too.

## Colour

- **Tokens only.** Colours come from semantic tokens in `styles.css` (`bg-background`, `bg-card`, `text-foreground`, `text-muted-foreground`, `bg-primary`/`text-primary-foreground`, `secondary`, `muted`, `accent`, `destructive`, `success`, `warning`, `border`, `input`, `ring`, plus `primary-edge` and friends for the chunky button edge). Never `bg-white/10`, `text-red-300` and similar. Exceptions: the answer palettes in `styles.css` (read through `option-colours.ts`), the QR code's white background (cameras need dark on white), the white tile behind a host's logo (`BrandingMark`; logos are made for light backgrounds), the medal colours, the editor's eight colour tags (`--tag-*` in `styles.css`, set as `--tag` through `tagStyle` from `lib/tags.ts` and used as `bg-(--tag)`; stripes and tints only, never behind text) and the cow logo's fixed brand colours (`public/logo.svg` and its layered copy in `cow-logo.tsx`; change both together).
- **Mixing with `--card` or `--border`: use `color-mix(in srgb, …)`.** White `--card` is `oklch(1 0 0)` with hue 0, so an oklch mix drags the hue: green turns beige in light mode and teal in dark. oklch mixes are fine between two saturated colours or with `black`/`transparent`.
- **Colour mode**: `light`, `dark` or `system` per device in localStorage `quizmoo.mode`, applied as `data-mode` on `<html>` before first paint by `public/mode-init.js` (a file, not an inline script: the CSP allows scripts from `'self'` only). `lib/mode.ts` is the store (`useMode`, `setMode`). `dark:` variants follow `data-mode`. Tokens have light values under `:root` and dark values under `:root[data-mode='dark']`, so most components need no `dark:` class at all.
- **Game themes**: `settings.theme` (playful `classic`, `arcade`, `sunset`, `mint`, `ocean`, `berry`, `forest`; subdued `graphite`, `navy`, `petrol`, `stone`, `bordeaux` for formal events, with chroma below 1) is a quiz setting. `/play/$pin`, `/screen/$pin` and `/host/games/$pin` call `useGameTheme(snapshot.settings)`, which sets `data-theme` and `data-palette` on `<html>` (so dialogs and toasts in portals follow them). A theme only overrides `--hue`, `--hue-accent`, `--tint` and `--chroma`; every token is computed from them, so both modes keep their contrast. The tokens are declared on `:root` and on every `[data-theme]` element, so a theme on a wrapper (the editor's phone preview) renders inside the page without changing it. Swatches for pickers come from `lib/themes.ts`, which mirrors the hues in `styles.css`. The `custom` theme takes the same three values from `settings.customTheme` (`hue`, `accent`, `chroma`, picked on `ColourWheel`): `themeVars()` sets them as inline variables on the element with `data-theme="custom"` (`useGameTheme` on `<html>`, the editor preview on its wrapper); the `[data-theme='custom']` block in `styles.css` is only the fallback. Never let a theme set lightness: that is what keeps contrast for any picked colour. The one exception is the Halloween season theme: its hue is orange, its surface tokens (background, card, muted, secondary, border, input, blobs) stay purple and lean towards black in both modes, and its primary tokens are set by hand (a burnt orange with white text in light mode, a bright pumpkin with dark text in dark mode, since `text-primary` must also reach 4.5:1 on the background, and `--primary-edge` must keep 4.5:1 with `--primary-foreground` for the projector's key hint); re-run `e2e/a11y.e2e.ts` during the season (or with a preview) after changing them. The answer palette works the same way: `custom` takes six free `#rrggbb` colours from `settings.customPalette`, `paletteVars()` sets `--option-N` and a computed `--option-N-fg` (`textOn`: white or dark by WCAG contrast) inline; every element with `data-palette` must also get `paletteVars` (or `gameVars` for both), or it falls back to Vivid. The accent hue shows only in the lobby card, the avatar bubble, the podium winner and the backdrop, so pickers need their own sample to show it.
- **Answer options** are identified by index. Their colours come from the game's answer palette (`settings.answerPalette`: `vivid`, `candy`, `neon`, `earth`, and the calm `muted`, `corporate`; six colours per palette in red, blue, yellow, green, orange, purple families, defined in `styles.css` under `[data-palette]` and read through `optionVars(index)` + `optionFill` from `option-colours.ts`) and their marks from the symbol set (`settings.answerSymbols`: `shapes`, `letters`, `numbers`, `icons`; `OptionSymbol` in `icons.tsx`). Colour is never the only signal. Palettes are independent of the theme and the colour mode, so answers never blend into the background.

## Look

- **Tooltip tails on the side:** Radix rotates the arrow for left and right placements and it lands about 2 px outside the bubble, so the tail's fill reaches 3 px into the bubble (`ui/tooltip.tsx`). Check side tooltips at 4× when touching the tail.
- **No scroll box inside a dialog** (user, 12 November 2026, on the budget dialog): use the width first, fields in columns (`FormDialog wide`, two columns from `sm`); only a phone may scroll, and then the whole dialog (`FormDialog` caps it at the viewport), never a `max-h` box inside it.
- **Round icon buttons on the same screen share one size** (user, 12 November 2026): on game screens that is the game menu's `size-11` with a `size-5` icon (the reaction button in the opposite corner matches it). Before adding a floating or corner icon button, look up the size of the ones already on that screen and reuse it.

Nunito (self-hosted via `@fontsource-variable/nunito`, never a font CDN), headings `font-black`/`font-extrabold`, 12 to 24 px radii (`rounded-xl` to `rounded-2xl`), `shadow-soft` on cards, solid buttons with a darker bottom edge that sink when pressed. Cards that carry a status get a visible identity: a solid tinted header and border, not a faint transparent wash.

**Tooltips** (phase 57): every control whose meaning is not written on it (an icon, a picture, a label hidden at some width with `sr-only` / `max-xl:sr-only`) gets a `Hint`, usually with its `aria-label` as the text. `e2e/hints.e2e.ts` enforces this at 1024 and 1440 px on the pages it visits (`e2e/hint-check.ts` finds controls without visible text and without `Hint`'s `data-hint` mark); a new page or panel with such controls goes into its walk. `data-no-hint` exempts a control whose picture is the point. Never `title`; wrap the element in `Hint` (`components/hint.tsx`, label empty = no tooltip). The bubble is `.tooltip` in `styles.css`: the toasts' look in small (popover colour, a border and 4 px edge mixed with the primary colour, a tail drawn as SVG whose fill covers the border where they meet), with a pop on the first open and a fade when moving to the next. One `TooltipProvider` in `__root.tsx` sets the delays. Radix opens them on hover and focus, never on touch; `Hint` also skips focus that is not `:focus-visible` (focus a dialog or menu hands back after a click). Inside another Radix trigger put `Hint` innermost (`<DropdownMenuTrigger asChild><Hint><Button>`; tabs: `<TabsTrigger asChild><Hint><button>`): the outer trigger's `data-state` then wins, otherwise the tooltip's `closed` / `delayed-open` replaces the menu's `open` and its open styles break. Only one tooltip shows at a time, so give a tile's hint to its name, not to the whole tile around other hints. Keep the bubble without an exit animation: a bubble still fading out closes itself when its trigger reopens it (it hears its own open event). A disabled button gets no pointer events, so its hint never shows; wrap it in a focusable `span` if the hint explains why it is disabled (the editor's Play).

**Tour bubbles** (phase 34) are the tooltip bubble in large (`.tooltip.tour-card`), with `.tour-spotlight` (a hole in a light dim, `--tour-dim`, darker in dark mode) and `.tour-ring` (a primary ring with a pulse) around the element. Dim and ring take no clicks: a tour never blocks the page.

**Seasonal decorations** (`features/season/`: `drawings.tsx` floating pieces, `scenes.tsx` edge strips and corners, `particles.tsx` falling pieces; the cow's costumes in `cow-logo.tsx`) use fixed festive colours with the ink outline, like the cow. Edge strips repeat one tile through an SVG `<pattern>` in a wide viewBox with `preserveAspectRatio="xMidYMin slice"`, so they scale with the strip's height. In a tile, fill closed shapes without a stroke and stroke only the open edge path (a closed outline shows as a seam at every tile edge), and make the tile width a whole multiple of anything repeated inside it. Snow and ice colours come from `--season-drift`, `--season-drift-shade` and `--season-ice` (dimmer in dark mode, so light text over them stays readable).

## Accessibility

Every interactive element shows a focus ring (`focus-visible:ring-[3px] focus-visible:ring-ring`); text meets 4.5:1 in both modes (`e2e/a11y.e2e.ts` runs axe in both modes); `prefers-reduced-motion` ends all CSS animations and transitions immediately (global rule in `styles.css`).
