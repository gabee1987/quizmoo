# Quiz editor (`/host/quizzes/$quizId`)

General web rules are in `web-ui`; the settings column's animation is in `motion`.

- **Layout**: at `xl` three panes (sortable `QuestionList`, the selected question's `QuestionToolbar` + `QuestionForm`, the `PhonePreview` at 82 % zoom); at `lg` list and form, preview behind a toggle; below `lg` the form alone, the list in a bottom `Sheet` opened from a fixed bottom bar. Title, `SaveIndicator`, `ProblemsMenu`, settings and Play live in the top bar, which sticks to the top from `sm`. The settings (tabs as on My settings: General with the description and Delete quiz, one tab per `GameSettingsForm` group, Branding) dock as a third column at `xl`, replacing the list so the preview stays visible while themes are chosen (non-modal, Escape closes it); below `xl` they open in a right `Sheet`. The host sidebar is hidden on this route (`routes/host/route.tsx`).
- **Draft** is one `QuizInput` in state; edits go through the pure helpers in `features/editor/draft.ts` (`insertQuestion`, `duplicateQuestion`, `removeQuestion` / `restoreQuestion` for undo, `move` for questions and options). Delete has no confirmation; a Sonner toast with "Undo" restores the question for 10 s.
- **Drag and drop**: `@dnd-kit` through `lib/sortable.ts` (`useSortableSensors`: mouse after 4 px, touch after a 250 ms hold, keyboard; `useSortableAccessibility` for translated announcements; `dragMove`). Keyboard drag starts from a handle button; mouse and touch may drag the whole row. Keep a non-drag alternative (move buttons) for every sortable list.
- **Groups in the list**: `listItems` / `fromItems` in `draft.ts` turn the draft into one flat list of group headers, questions and group end rows (`endId`); a question between a header and its end is in that group, so every reorder of the list is also the group change. Drops are "before or after a row" (`placeQuestion`, `placeGroup`); groups move as blocks (`placeGroup`, `stepGroup`). `QuestionList` uses dnd-kit's vertical strategy (it measures drop targets without transforms, so rows that move aside do not jitter); the dragged row itself is the dashed ghost card, framed by the group it would land in, and the drop side follows the movement (down: after the row it is over, up: before). Every row is gapless (spacing is padding inside it) so rows move aside by exactly the ghost's height. Collision is by the pointer's height only, so a row's or a group's whole width takes the drop. A group is one card: the header is its top, the end row (`GroupEnd`, always rendered) its rounded bottom with the count badge, and the question rows between carry its sides (grouped questions are borderless `bg-card` cards on the group's tint, ungrouped ones `bg-muted/70`; a question with a colour looks like a group card: `--tag` border at 40 % (solid when selected), a 10 % tint over `bg-card` so a group's tint does not add to it, and the icon chip at 25 %). Closed, the header's contents slide down by half the bottom piece (`*:translate-y-2.75`, the header row at `z-1` so they pass over it), centring them in the whole card; its fold arrow is a round chip so its hover fits the corner. The bottom piece is as tall as the radius (`rounded-2xl` is 24 px here), or the browser shrinks its corners below the top's. Closed groups keep their rows mounted, shrunk with `grid-template-rows` and inert, so the bottom slides up and down with nothing switching shape; that transition goes in the row's inline style next to dnd-kit's `transition`, which otherwise replaces it and makes opening instant. Check such animations frame by frame (several distinct heights), since an instant jump also passes a "moves monotonically" check. `useFlipOnReorder` is keyed by the order of every row, not the visible ones, so opening or closing slides nothing, and it re-measures on resize. The drag overlay is portalled to `body` (z 1001) so it passes over the trash panel, which floats left of the list's panel without moving anything and takes a drop only once the pointer is 12 px left of where the drag started. Keyboard drags pick the side by direction and never reach the trash. An empty group's place exists only in the editor (`Layout.emptyAfter`, stripped before saving); change the layout through these helpers (or `fromItems(listItems(...))`), not by editing `questions` directly, or an emptied group jumps.
- **Validation**: `validateQuiz` runs the shared schema; `locateProblem(path)` maps an error path to its question, a label and the `data-field` of the element to focus. Every editable field that can be invalid carries `data-field="<error path>"` (wrappers are fine: the first focusable inside gets focus). New questions show their errors only once visited.
- **Saving**: `useAutosave` returns `{ status, retry }` with `saved | pending | saving | invalid | offline | error`; offline saves retry on the `online` event and every 10 s. `useBlocker` asks before leaving while the status is `invalid`, `offline` or `error`, and the browser's own prompt covers closing the tab while anything is unsaved.
- **Shortcuts**: `matchShortcut` in `shortcuts.ts` (ignored while a field, dialog or menu has focus); list them in `shortcutKeys` so the "?" dialog stays complete.

## Quiz branding

`QuizBrandingFields` (`features/editor/quiz-branding-fields.tsx`) sits under the Look group: show on or off, a logo and an event name that override My settings when filled. It is quiz data (`draft.branding`), not a game setting, so batch edit, game defaults and the settings summary leave it out.

## Quiz files

Formats in `docs/quiz-files.md`. The spreadsheet reader and writer (`packages/shared/src/quiz-csv.ts`) and the Quizmoo file schema (`quiz-file.ts`) are shared and pure; the browser part is `features/host/quiz-files.ts` (`exportQuiz`, `templateCsv`, `readQuizFile`) and `import-quiz-dialog.tsx`. Columns are by position and the type words are format tokens in `csvTypeWords`, not translations; the guide rows, headers and template examples are i18n (`quizFile.*`, arrays read with `returnObjects`). A new question field needs a column (or a note that spreadsheets leave it out) and a round-trip case in `quiz-csv.test.ts`.

## Game settings groups

`GameSettingsForm` is split into three groups (Game flow, Look, Scoring), labelled with the batch edit's keys (`host.batch.groups.*`) so every dialog names them the same way. `sectionSummary(group)` gives a group's chips; `settingsSummary` is built from it. The new game dialog shows one card per group, one open at a time, with "Changed for this game" and "Reset" when a group differs from the quiz's defaults.
